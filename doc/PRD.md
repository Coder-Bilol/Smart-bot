# Техническая спецификация для Telegram-бота (Smart Bot)

## 1. Обзор
Этот документ описывает архитектуру и логику работы **Smart Bot** — Telegram-бота, который использует LLM (через OpenRouter) для поддержания осмысленной беседы в групповых чатах. Бот способен адаптироваться к контексту, принимать различные роли и управлять параметрами генерации ответов.

## 2. Конфигурация
Все настраиваемые параметры хранятся в файле `.env` и загружаются при старте.

### Переменные окружения:
- `TG_TOKEN`: API-токен для Telegram Bot API.
- `RESPONSE_DELAY`: (Целое число) Базовая задержка в секундах перед ответом (по умолчанию 5).
- `TG_ADMIN_ID`: (Опционально) ID администратора для специфических команд (если применимо).
- **API Ключи моделей (OpenRouter):**
  - `OPENROUTER_KEY_ZAI`: Ключ для модели Z.ai GLM.
  - `OPENROUTER_KEY_QWEN`: Ключ для модели Qwen.
  - `OPENROUTER_KEY_KIMI`: Ключ для модели Kimi.

## 3. Архитектура и Хранение данных

Бот использует гибридную систему хранения данных:
1.  **SQLite (Persistent)**: Долгосрочное хранение настроек чатов и истории переписки.
2.  **RAM (Transient)**: Краткосрочное хранение активных таймеров и флагов состояния.

### 3.1. База данных (SQLite)
Файл: `bot_database.db`

#### Таблица `chats` (Настройки)
| Поле | Тип | Описание |
|------|-----|----------|
| `chat_id` | INTEGER PK | ID чата Telegram. |
| `custom_role` | TEXT | Пользовательское дополнение к системной роли. |
| `custom_goal` | TEXT | Пользовательское дополнение к цели бота. |
| `timeout_seconds` | INTEGER | Персональная задержка ответа для чата. |
| `model` | TEXT | ID используемой модели LLM. |
| `is_active` | INTEGER | Флаг активности режима разговора (0/1). |
| `created_at` | TIMESTAMP | Дата первого взаимодействия. |

#### Таблица `messages` (История)
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | Автоинкремент. |
| `chat_id` | INTEGER FK | Ссылка на чат. |
| `role` | TEXT | Роль отправителя (`user`, `assistant`). |
| `content` | TEXT | Текст сообщения. |
| `timestamp` | TIMESTAMP | Время сообщения. |

### 3.2. Состояние в памяти (`active_chats`)
Словарь `active_chats` инициализируется при старте (восстанавливая данные из DB) и содержит:
- `key`: `chat_id`
- `value`:
  - `timer`: Объект `asyncio.Task` (активный таймер ответа).
  - `is_waiting_for_user`: Флаг (True, если бот ответил и ждет реакции).
  - `reply_to_message_id`: ID сообщения, на которое бот должен ответить (для контекста реплаев).

## 4. Логика работы

### 4.1. Команды управления (Admin/User)

#### Управление состоянием
- **/startconv**: Активирует режим разговора.
  - Записывает `is_active=1` в БД.
  - Бот начинает слушать все сообщения в чате.
- **/stopconv**: Деактивирует режим разговора.
  - Отменяет текущие таймеры.
  - Записывает `is_active=0` в БД.
- **/statusconv**: (Admin) Показывает текущие настройки: статус, роли, цели, модель, таймаут.

#### Настройка личности (Admin)
- **/role [текст]**: Устанавливает `custom_role`. Без аргументов — сбрасывает.
- **/goal [текст]**: Устанавливает `custom_goal`. Без аргументов — сбрасывает.
- **/timeout [секунды]**: Устанавливает персональную задержку ответа.

#### Выбор модели (Admin)
- **/model**: Выводит меню с inline-кнопками для выбора LLM из доступных (`MODEL_CONFIGS`).

### 4.2. Алгоритм обработки сообщений
1.  **Фильтрация**: Бот реагирует только если чат находится в `active_chats` (или если вызвана команда).
2.  **История**: Сообщение пользователя сохраняется в БД (`messages`).
3.  **Сброс флагов**: Если установлен `is_waiting_for_user`, он сбрасывается.
4.  **Обработка реплаев**:
    - Если сообщение — **ответ на сообщение бота**:
      - Задержка устанавливается в **0 секунд** (мгновенный ответ).
      - `reply_to_message_id` сохраняется.
    - Иначе (обычное сообщение):
      - Задержка берется из настроек чата или глобального `RESPONSE_DELAY`.
5.  **Таймер**:
    - Если уже был запущен таймер — он **отменяется** (debounce logic).
    - Запускается новый таймер на вычисление ответа.

### 4.3. Генерация ответа
Функция вызывается по срабатыванию таймера:
1.  Отправляется статус "typing".
2.  **Сборка промпта**:
    - Читаются файлы `doc/prompting/role_prompt.md` и `goal_prompt.md`.
    - Добавляются `custom_role` и `custom_goal` из БД.
    - Формируется системное сообщение.
3.  **Контекст**: Извлекаются последние 50 сообщений из БД.
4.  **API Запрос**: История (+ системный промпт) отправляется в OpenRouter (модель из настроек чата).
5.  **Отправка**: Ответ публикуется в чат (как reply, если это был ответ на сообщение бота).
6.  **Сохранение**: Ответ бота сохраняется в БД.
7.  **Ожидание**: Устанавливается флаг `is_waiting_for_user = True` (бот замолкает до следующей реплики человека).

## 5. Интеграция с LLM (OpenRouter)
- Используется библиотека `openai` с `base_url="https://openrouter.ai/api/v1"`.
- Каждый запрос подписывается API-ключом, соответствующим выбранной модели.
- Заголовки `HTTP-Referer` и `X-Title` передаются для соблюдения требований OpenRouter.

## 6. Заблокированные папки
- `spec/`: Устаревшие спецификации, не использовать.
- `.memory/`: Служебная информация, не редактировать вручную.
