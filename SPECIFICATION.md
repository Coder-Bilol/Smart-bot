# Техническая спецификация для Telegram-бота с интеграцией Gemini

## 1. Обзор

Этот документ описывает архитектуру и логику работы Telegram-бота, который использует нейронную сеть Google Gemini для поддержания беседы в групповых чатах.

## 2. Конфигурация

Все настраиваемые параметры должны храниться в файле `.env` и загружаться при старте бота.

- `TG_TOKEN`: API-токен для Telegram Bot API.
- `VOIDAI_API_KEY`: API-ключ для VoidAI API.
- `RESPONSE_DELAY`: (Целое число) Задержка в секундах, после которой бот отвечает, если в чате нет новых сообщений. Рекомендуемое значение: `5`.

## 3. Управление состоянием

Состояние бота будет храниться в оперативной памяти в виде словарей. При перезапуске бота состояние будет сбрасываться.

### 3.1. Активные чаты

Словарь для отслеживания чатов, где активирован режим разговора.

- **Структура:** `active_chats = {}`
- **Ключ:** `chat_id` (ID чата)
- **Значение:** Словарь с состоянием конкретного чата (см. п. 3.2).

### 3.2. Состояние чата

Для каждого активного чата будет храниться следующая информация:

- `message_history`: Список сообщений для контекста нейросети (последние 50 сообщений).
- `timer`: Объект таймера (`asyncio.TimerHandle`), который отсчитывает задержку для ответа.
- `is_waiting_for_user`: Булевый флаг. `True`, если бот уже дал ответ и ждёт сообщения от другого пользователя. `False` в противном случае.

**Пример структуры для одного чата:**
```python
# chat_state[12345678]
{
  "message_history": [
    {"role": "user", "content": "Привет! Как дела?"},
    {"role": "user", "content": "Кто-нибудь тут есть?"}
  ],
  "timer": <asyncio.TimerHandle object>,
  "is_waiting_for_user": False
}
```

## 4. Логика работы

### 4.1. Команды управления

- **/startconv**:
  1. Проверить, не активирован ли уже режим в этом чате.
  2. Если нет, добавить `chat_id` в `active_chats` с пустым состоянием.
  3. Инициализировать `message_history`, установить `is_waiting_for_user` в `False`.
  4. Отправить в чат сообщение: "🤖 Режим разговора активирован. Я присоединюсь к беседе, если будет пауза."

- **/stopconv**:
  1. Проверить, активирован ли режим в этом чате.
  2. Если да, отменить активный таймер (если он есть).
  3. Удалить `chat_id` из `active_chats`.
  4. Отправить в чат сообщение: "🤖 Режим разговора отключён."

### 4.2. Обработка сообщений

Этот обработчик должен срабатывать на все текстовые сообщения в чатах.

1. Получив сообщение, проверить, есть ли `message.chat.id` в `active_chats`. Если нет — игнорировать.
2. Получить состояние для текущего чата: `state = active_chats[message.chat.id]`.
3. **Проверка флага ожидания:**
   - Если `state['is_waiting_for_user']` равно `True`:
     - Сбросить флаг: `state['is_waiting_for_user'] = False`.
     - Продолжить обработку.
4. Добавить новое сообщение в `state['message_history']`. Формат должен быть совместим с VoidAI API.
5. **Управление таймером:**
   - Если в `state` уже есть активный таймер, отменить его.
   - Создать новый таймер, который через `RESPONSE_DELAY` секунд вызовет функцию для генерации ответа (`generate_response(chat_id)`).
   - Сохранить объект таймера в `state['timer']`.

### 4.3. Генерация и отправка ответа

Эта функция вызывается по истечении таймера.

1. Получить `chat_id` в качестве аргумента.
2. Получить состояние чата `state = active_chats.get(chat_id)`. Если чат уже неактивен, прекратить выполнение.
3. **Проверка флага ожидания:** Если `state['is_waiting_for_user']` равно `True`, прекратить выполнение (это дополнительная проверка на всякий случай).
4. Отправить в чат индикатор `typing` с помощью `bot.send_chat_action`.
5. Отправить `state['message_history']` в VoidAI API (последние 50 сообщений для контекста).
6. Получить сгенерированный текст ответа.
7. Отправить ответ в чат. Это действие автоматически уберёт индикатор `typing`.
7. Установить флаг ожидания: `state['is_waiting_for_user'] = True`.
8. Добавить ответ бота в историю сообщений `state['message_history']` и ограничить историю последними 50 сообщениями.

## 5. Интеграция с VoidAI

- Будет использоваться библиотека `httpx` для асинхронных HTTP-запросов.
- Запросы будут отправляться на эндпоинт `https://api.voidai.com/v1/chat/completions`.
- Аутентификация будет производиться через заголовок `Authorization: Bearer <VOIDAI_API_KEY>`.
- Модель `gemini-2.5-flash` будет указываться в теле JSON-запроса.
- История сообщений будет передаваться в формате, который требует API (список словарей с полями `role` и `content`).
